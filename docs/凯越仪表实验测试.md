# 凯越仪表（实验）测试

## 当前实现

2026-11-27 新增独立 `koveInstrument` Profile，菜单显示“凯越仪表（实验）”，放在 625X 附近。旧模式编号不变，原 625X 继续使用 Yunmo。新路径基于凯越 Android App 1.1.7 的 Erya 协议分析，尚无实车通过记录，不按车型名称宣称兼容。

实现：独立控制/画面 TCP，OK 尺寸协商，开始请求重发，JPEG 时间戳封包，ACK 单帧许可、只采样最新画面，12 秒心跳/ACK 超时及停止唤醒。只接受明确的 JPEG 420；H.264、422 和其他参数明确报错，避免发送错误编码。发送目标上限 10 FPS，实际速度受仪表 ACK 限制。

## 发给测试者

1. 车辆停稳，打开仪表互联页面；先确认官方凯越 App 能连接和投屏，记录车型、仪表型号及固件版本。
2. 退出官方 App 的投屏连接，让 iPhone 手动加入同一仪表 Wi-Fi。
3. CarWithin 选择“凯越仪表（实验）”。在连接设置中填写仪表 IP；IP 留空只尝试当前网段的 `.1`，不是扫描发现。画面 TCP 默认 **11111**，控制 TCP 默认 **11113**，仪表二维码提供其他值时按二维码填写。
4. 核对 CarWithin 的 Wi-Fi 预设，先前台启动 CarPlay。观察手机预览与仪表画面是否分别出现，再检查比例、颜色和延迟。
5. 停止后重新连接一次，再测试断开 Wi-Fi 后重新加入并启动。
6. 成功或失败都导出诊断日志，附上车型、仪表固件、测试时间、官方 App 是否成功、手机预览是否有画面。涉及 Wi-Fi 密码的二维码只私下提供，公开反馈先遮挡。

目前不包含蓝牙配网、扫码、车把按键与触控回传。仪表若不支持 iPhone 手动加入 Wi-Fi，此路径尚不能解决配网问题。失败不代表所有凯越仪表不兼容，也不建议反复尝试其他升级端口。

## 诊断阶段

- `Erya control TCP/connected`：控制端口连接；失败先核对 IP、端口、Wi-Fi 和官方 App 是否占用。
- `Erya video TCP`：开始画面端口连接。
- `start request/awaiting OK`：请求已发送，等待仪表尺寸/编码回复。
- `negotiated`：已经收到有效尺寸与 JPEG 420 参数。
- `JPEG sent frame=1`：已收到发送许可，首帧已经写入 TCP；仍不等于仪表已显示。
- 首帧后等待 ACK 超时：需结合仪表画面与后续日志判断接收情况。

日志只记录端点、协商尺寸/编码、发送帧数和长度，不记录原始控制 JSON、密码或 JPEG 内容。

## 验证与交付状态

`Tools/test_motorcycle.sh` 包含 Erya 独立字节样例、控制大端长度、分段 OK 响应、畸形长度和尺寸拒绝，以及真实本机双 TCP 的协商、ACK 背压、单帧许可与停止唤醒；同时运行原 Yunmo/ThinkerRide 回归。本轮上述模拟及原协议回归通过，iOS arm64 Release 无签名构建通过。模拟仪表验证不能代替车辆验收。

本轮保持 Info.plist 版本号和构建号不变；仅本地实现，没有安装到手机、分发 IPA、推送或公开发布。编译和测试日志放在 `.local/kove-erya-profile-20261127/`。

## 仪表二维码补充证据

用户随后提供真实仪表照片，Core Image 与 Vision 均解码一致。二维码为凯越链接，连接参数 `name=AP`、`IP=192.168.4.1`、`port1=8200`，未提供 `port2`；SSID为KY_ADV前缀且与测试截图对应。密码、key及完整设备标识仅限私有材料，不在报告中展开。

这纠正了对默认11111适用性的假设：该车二维码明确指定port1为8200，下一次Erya测试应将画面端口改为8200。控制端口11113只是当前默认且曾TCP建立，二维码没有确认它。二维码本身不能确认8200接受AA BB CC还是FE协议，也不能从key字段存在推断必需鉴权。此前“8200出现在升级服务”的静态证据不排除它同时用于该仪表投屏，不应再据此怀疑8200不是该车投屏端口。
